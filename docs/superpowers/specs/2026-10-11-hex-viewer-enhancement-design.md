# 设计：hex 查看器自研增强（跳转 offset / 搜索 / 数据检查器）

- 日期：2026-10-11
- 状态：已评审（spike 结论用户确认「自研增强」，待实施）
- 关联：`docs/report/hex-viewer-spike-2026-10-11.md`（选型依据）、`2026-10-06-vviewer-design.md`（hex 渲染器与 BUG-14/16 修复）、`packages/render-binary`（hex.ts/hexBytes.ts/struct.ts/binary.worker.ts）

## 1. 背景与目标

现状：自研 hex 查看器具备三列 dump、结构树（ELF/ZIP）、虚拟滚动与 worker 化读取，性能达标；**无跳转、无搜索、无数据检查器**。选型 spike 结论：外部库只解决渲染（已自研达标），功能缺口按自研补齐，交互设计借鉴 MIT 的 vscode-hexeditor。

目标：在 `packages/render-binary` 增量补三块能力——跳转 offset、文件内搜索、光标处数据检查器——全部 worker 内增量执行，不破坏既有虚拟滚动与首屏性能。

### 已拍板的决策（spike + brainstorm 记录）

| 决策点 | 结论 |
| --- | --- |
| 实施路线 | 自研增强，不集成外部库（spike 六候选核实结论） |
| 优先级与交付 | 跳转 → 搜索 → 检查器，三块独立可交付、各自 commit（TDD） |
| 搜索模式 | hex 字节串 + UTF-8 文本两种（文本按 UTF-8 编码为字节序列；大小写开关默认敏感） |
| 命中上限 | 1000 + `truncated` 标记（对齐全局搜索 `MAX_MATCHES` 惯例） |
| 扫描执行 | worker 增量分块扫描 + 进度上报 + 取消；跨块匹配用 needle 长度-1 的块间重叠 |
| 检查器位置 | **MetaPanel 新增「数据检查器」区块**（hex 实例激活且光标存在时显示），复用既有右栏布局与移动端抽屉，不在渲染器内自造第二套面板 |
| 高亮渲染 | 行渲染由整串改为按需 span 切分：仅命中行/光标行切分，其余行维持整串零开销 |
| 非目标 | 不做编辑/另存；不做 pattern language 与结构解析扩充（struct.ts 另行立项）；不做位级注释（远期借鉴）；不做书签/多高亮集 |

## 2. 设计

### 2.1 跳转 offset（阶段 1）

- hex 视图顶部新增工具条（sticky）：跳转输入框 + 搜索输入框（阶段 2 启用）+ 命中计数与进度位。
- 跳转语法消歧义：`0x` 前缀按十六进制，其余按十进制（placeholder 注明）；空输入不动作。
- 定位：`row = floor(offset / 16)`，经既有虚拟滚动 API 滚至目标行（目标行居中偏好）；超界 clamp 到文件最后一个字节并提示「已跳至文件尾」。
- 目标字节短暂高亮（约 1s 衰减），复用 §2.3 的 span 切分渲染。

### 2.2 文件内搜索（阶段 2）

- **输入解析**：hex 模式接受可选空格分隔的字节串（`de ad 09` / `dead09`），奇数个 hex 位 → 输入框内联错误提示（非弹层）；文本模式按 UTF-8 编码为字节序列（ASCII 即子集）。
- **扫描协议**（`binary.worker.ts` 新任务）：分块（1MB）+ needle 长度-1 重叠，逐块推进；每块后上报 `{scanned, total}` 进度；命中累计达 1000 → 提前终止并标 `truncated`；新搜索 / 实例销毁 / 文件重载 → 取消旧任务（cancel token）。
- **命中消费**：命中列表（offset 升序）驻 worker 侧，主线程持有镜像；工具条显示「n 处命中（截断）」+ 进度；`Enter`/`Shift+Enter` 与上一处/下一处按钮循环导航，当前命中滚动定位。
- **高亮**：其他命中与当前命中两档配色；hex 列与 ASCII 列的对应字节同档高亮；命中跨行（16 字节边界）按行拆分渲染。

### 2.3 数据检查器（阶段 3）

- **光标**：点击 hex 列或 ASCII 列任意字节 → 换算 cursor offset（整行字符串渲染下按点击 x 坐标定位字节）；方向键微调（左右 ±1）；光标字节高亮。
- **解码面板**（MetaPanel「数据检查器」区块）：类型集 `int8/16/32/64`、`uint8/16/32/64`、`float32/64`、`bool`（非零即真）、UTF-8 片段（16 字节截断）、原始 hex 回显；**字节序切换 little/big（默认 little）**；cursor 处剩余字节不足的类型显示 `—`。
- **数据通路**：worker 按需读取 cursor 起 8 字节窗口解码（远端文件同样走 Range），经既有 metaStore 上行链路驱动 MetaPanel；不引入新的全局状态通道。
- 移动端：右栏已是抽屉，无额外适配。

### 2.4 渲染与性能护栏

- `renderHexBytes` 扩展可选「高亮区间」参数；无区间时输出与现状完全一致（回归零风险）。
- 工具条出现不改变行高/滚动数学；扫描与解码全在 worker，主线程仅收帧。
- 性能锚点：搜索期间与跳转后虚拟滚动首帧不劣化（复用 BUG-16 的 38ms 口径做前后对照）；200MB 文件发起搜索后 100ms 内出现首个进度帧。

## 3. 测试

- 单测：跳转语法解析（`0x`/十进制/非法/超界 clamp）；hex/文本 pattern 解析（空格、奇数位、UTF-8 多字节）；分块扫描纯函数（needle 恰跨块边界、首尾命中、1000 截断、进度推进、取消）；检查器解码表（已知字节序列逐类型断言、字节序两向、字节不足降级）。
- 集成：worker 任务全链路（含远端 Range 通道的窗口读取）。
- e2e：fixture 文件（已知字节布点）验证跳转/搜索/导航/两档高亮/检查器各类型；搜索中滚动流畅；结构树与既有能力回归。

## 4. 风险与已知限制

- 超大文件（GB 级）全文扫描耗时随进度条与取消兜底，不做索引缓存（每次搜索重扫；热点场景未来可加块缓存）。
- 行 span 切分仅命中/光标行启用，命中极密时（如搜索单字节 `00` 命中满屏）DOM 节点上升——受 1000 命中上限与可视区行数双重约束，量级可控。
- float 解码遵循 IEEE 754（NaN/Inf 原样显示）；文本搜索不做规范化（NFC/NFD 差异按字节忠实匹配）。

## 5. 验收

| 项 | 标准 |
| --- | --- |
| 跳转 | hex/dec 定位准确，超界 clamp，目标高亮可见 |
| 搜索 | 两模式命中数与全局搜索惯例一致（1000 截断）；跨块边界命中不漏；进度/取消/导航可用 |
| 检查器 | MetaPanel 区块类型解码正确、字节序可切、移动端抽屉可达 |
| 护栏 | 无高亮路径渲染输出与现状逐字节一致；性能锚点达标；vitest / typecheck / playwright 全绿 |

交付顺序：阶段 1 跳转 → 阶段 2 搜索 → 阶段 3 检查器；每阶段独立 commit，TDD。
