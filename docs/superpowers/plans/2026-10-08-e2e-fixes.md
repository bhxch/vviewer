### 1.4 与 spec 的实现落点裁决（已核实代码后定案）

1. **BUG-03 滚动目标走 DOM 查询，不改 ViewerPane**：`.vv-code-pre` 是 code 渲染器的稳定类名契约（`code.ts:357`，e2e 也按此类名断言），AppShell 的 j/k/gg/G 处理器直接 `document.querySelector('.vv-viewer-host .vv-code-pre')`（回落外层 `.vv-viewer-scroll`），与 spec「活动实例 getScrollHost() 否则外层容器」语义等价，但避免 ViewerPane（归包 2）与 AppShell（归包 5）的文件冲突。
2. **BUG-09 的 pendingLine 用对象扩展字段**：`Object.assign(tab, { pendingLine: m.line })` 写入（`addTab` 返回 tab，`GlobalSearchPanel.svelte:143`），ViewerPane 以 `'pendingLine' in tab` 探测消费。`snapshot()` 是显式字段拷贝（`openFlow.svelte.ts:31-45`），天然不持久化，满足 spec「随快照不持久化」，且不改包 5 独占的 `openFlow.svelte.ts` 的 `Tab` 接口。
3. **BUG-10 的路由注入走 `attachHighlightRouter` 独立回调**（spec 方案 2 的备选）：`code.ts` 新增模块级 router 注入位（与 `attachHighlightClient` 同模式，`code.ts:308-318`），实现在包 2 新文件 `apps/web/src/lib/highlightRouter.ts`，`import { computeRouter } from './highlightClient'`（该导出已存在，`highlightClient.ts:59`）——零改动包 3 独占的 `highlightClient.ts`。
4. **BUG-14 的重试闭包渲染器/dispatcher 自持**：`renderer.render(buffer, target, source, det)` 的参数在 render 作用域内齐全，av 渲染器与 dispatcher catch 分支各自持有重渲染闭包，`core` 不反向依赖应用层（与 spec「ViewerPane 注入」目标一致，落点更内聚）。
5. **BUG-07 是包 1↔包 2 的跨包契约**（详见 §3.1 握手点 1）：派发回退链在包 1，shebang→高亮的 `det.lang` 消费行在包 2。
