# 多端发布阶段三：Workers 适配 Implementation Plan（spec 阶段三）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `server/worker` workers-rs 适配：fetch handler→core dispatch；HttpTransport 的 wasm fetch 实现（storage 唯一来源=S3/WebDAV 挂载）；VV_MOUNTS env JSON 配置；静态资产 Workers Assets binding（SPA fallback+资产 404 不回 HTML）；部署 CI（wrangler deploy+canary 探活）+体积门禁 <5MB。

**Architecture:** 阶段二已就绪 core（CoreRequest/CoreResponse/CoreState + 八域 handler + feature 门控）——本计划三件：①**前置项（终审 I-1）**：core 的 storage 依赖解耦（`vviewer-storage` native 转发 feature + CoreState 懒构造挪出/门控——worker 形态以注入 transport 构造）；②workers-rs `server/worker` crate：fetch→core 双向映射 + wasm `HttpTransport`（worker Fetch binding）；③wrangler.toml（assets binding `run_worker_first: ["/api/*"]`、not_found_handling SPA fallback、`.wasm/.scm/.mjs` 缺失 404 不回 HTML）+ `VV_MOUNTS` env JSON（结构同 TOML [[mount]]）+ CI deploy workflow+canary+体积门禁。

**Tech Stack:** workers-rs（worker crate）、wasm-bindgen、tokio-util compat（futures↔tokio 流桥）、wrangler、vitest/cargo。

**Spec:** `docs/superpowers/specs/2026-10-19-multiplatform-release-design.md` 阶段三

## Global Constraints

- **前置项兑现（终审 I-1）**：core 的 storage 依赖改 `optional`+`native` 转发 feature；CoreState 懒构造 `ReqwestTransport::new()` 硬编码挪出（构造注入 transport 或 native-only 构造路径）；native 形态行为零变化（既有测试零改动锚）。
- worker 形态能力矩阵：无 watch（events 路由不挂载或 501+health 不宣告）、无 rg 搜索（search 路由 501/不挂载+health 不宣告 searchEngine）、无 compute（阶段二 feature 已裁剪——`--no-default-features` 等价的 cargo feature 组合）；mounts 三 API 与 file/tree 经 S3/WebDAV backend **可用**。
- 静态资产纪律（C1 SPA-fallback 前科）：`.wasm`/`.scm`/`.mjs` 等资产缺失必须 404 不回 HTML；`run_worker_first: ["/api/*"]`；`VV_BASE_PATH` 构建注入链复用。
- `/api/file` Range 响应直通流式（ReadableStream 穿透不整块缓冲）；gzip 不做（worker 出口压缩语义差异，注记）。
- 体积门禁：worker 脚本产物（wasm+js）<5MB，CI 断言。
- VV_MOUNTS env JSON 结构同 TOML [[mount]]；凭据走 Wrangler Secrets。
- 每任务原子提交；cargo 双形态测试；wrangler dev 冒烟。

### 实施风险与裁决预留

- workers-rs 生态版本与 wasm32 工具链（worker-build/wasm-pack）安装面——Task 2 实测校准，报告记录。
- axum-free 的 core dispatch 对 worker Request 的映射自由度（CoreRequest 字段形态在 Task 1 定型——若 Plan B T1 的 CoreRequest 零消费形态与本计划冲突，Task 1 的 CoreRequest 处置（删除/激活）在本计划重新裁决——终审 Minor-2 遗留）。
- SSE 不挂载的 health 口径：events 路由不挂载 vs 挂载即 501——取「不挂载+health 不宣告」与阶段二机制同形。
- canary 探活需要已部署实例——CI 探活步骤在无 CF 凭据时跳过（手动 dispatch 有 secrets 才跑）。
- ReadableStream 直通的 wasm 面（worker Response body 与 core ByteStream 的桥）——tokio-util compat 在 wasm 不可用（tokio 裁剪），需 wasm 侧流桥——实施实测校准，报告记录。
